## 0. Главное в одном экране

1. **Всё движение — от `useCurrentFrame()`.** Никаких CSS `transition`/`animation`, `setTimeout`, `Date.now()`, `Math.random()`. Рендер идёт кадр за кадром в произвольном порядке и параллельно: состояние «между кадрами» не существует.
2. **Ни одного линейного движения** без причины. По умолчанию ease-out (`Easing.bezier(0.16, 1, 0.3, 1)`) или `spring` без отскока (`damping: 200`). Линейно двигаются только бесконечные фоновые дрейфы.
3. **Появление — это несколько свойств сразу:** прозрачность + небольшой сдвиг (20–60 px) + размытие (8–16 px → 0) или маска. Одна только прозрачность выглядит дёшево.
4. **Стаггер.** Группа элементов появляется по одному с шагом 2–5 кадров (при 30 fps), а не одновременно.
5. **Выход быстрее входа** и с ускорением (ease-in), а не с замедлением.
6. **Ничего не стоит мёртвым.** Фон дрейфует, камера медленно наезжает (scale 1 → 1.04 за сцену), объект «дышит». Статичный кадр дольше 1,5 с выглядит как зависание.
7. **Один акцентный цвет, один шрифт (2–3 начертания), одна сетка** на весь ролик. Вкус — это прежде всего ограничения.
8. **Картинка служит голосу.** Текст и элементы появляются в момент, когда диктор это произносит (или на 2–4 кадра раньше), а не «когда-нибудь в сцене».
9. **Звук — половина ощущения качества.** Музыка ныряет под голос, акценты (удар, вжух, щелчок) стоят ровно на кадре события, громкость сведена (≈ −14…−16 LUFS, пики не выше −1 dBTP).
10. **Проверяй глазами.** Рендерь стоп-кадры на ключевых моментах и контактные листы, смотри их сам до того, как сказать «готово». Не утверждай того, чего не видел.

## 1. Как понимать пользователя

### 1.1. Сначала выясни задачу, потом пиши код

Перед первым кодом у тебя должен быть ответ на эти вопросы. Если ответа нет в сообщении, исходниках или прошлой переписке, задай вопросы **одним коротким списком** (не больше 3–5), остальное додумай разумными умолчаниями и проговори их.

| Что выяснить | Зачем | Разумное умолчание |
|---|---|---|
| Где будет показан ролик (YouTube, Reels/TikTok, экран на мероприятии, презентация) | Формат, длина, безопасные зоны, темп | 1920×1080, 30 fps |
| Длительность или «под голос» | Тайминг всего | Под голос/музыку; без них — 15–60 с |
| Есть ли голос, музыка, исходники, бренд-гайд | Что уже задано | Бренд по логотипу/скриншотам пользователя |
| Тон: строго-корпоративно, энергично-промо, дружелюбно-объяснялка, мемно | Стиль анимации, музыка, SFX | Из контекста материала |
| Референс («как вот этот ролик») | Самый точный источник вкуса | Нет — предложи 1–2 направления словами |
| Что категорически нельзя трогать | Не сломать чужую работу | Исходный звук и текст не менять |

### 1.2. Слушай буквально, понимай по смыслу

- **Буквальная правка выполняется буквально.** «Сдвинь плашку на секунду позже» — сдвигаешь именно её и ничего больше. Не «улучшай заодно» соседние сцены без спроса: пользователь сравнивает версии и злится, когда меняется то, о чём он не просил.
- **Оценочная жалоба требует расшифровки.** Переводи её в конкретные параметры:

| Пользователь говорит | Что обычно значит | Что крутить |
|---|---|---|
| «Топорно», «дёшево» | Линейные движения, всё появляется разом, только fade | Easing, стаггер, blur/маска, вторичное движение |
| «Скучно», «затянуто», «динамичнее» | Длинные статичные паузы, медленные входы | Короче холды, чаще смена кадра, быстрее входы (10–14 кадров), камера |
| «Слишком мельтешит», «рябит» | Много одновременных движений, отскоки, тряска | Меньше элементов в движении одновременно, убрать bounce, увеличить паузы |
| «Не попадает в голос» | Тайминг по сетке, а не по речи | Таймкоды слов (транскрипция), сдвиг `from` |
| «Текст не читается» | Мало времени, мелко, низкий контраст | ≥ 0,25 с на слово + 1 с, крупнее, подложка/тень |
| «Не в стиле бренда» | Шрифт/цвет/скругления не те | Взять из гайда/логотипа, не изобретать |
| «Звук бесит» | SFX слишком громкие, однотипные или на каждом чихе | Тише (−6…−12 dB), меньше, разнообразнее |
| «Как будто PowerPoint» | Слайды сменяются целиком, нет связей между сценами | Общие элементы между сценами (shared element), камера, перетекание |

- **Если жалоба неоднозначна, предложи интерпретацию и сделай.** «Понял „динамичнее“ так: сократил холды с 2 до 1,2 с и ускорил входы. Если имелось в виду другое — скажи». Это лучше, чем пять уточняющих вопросов.
- **Пользователь может править код сам** (в Studio или руками). Перед изменением файла перечитай его. Если видишь неожиданную правку, считай её намеренной и не затирай.

### 1.3. Как отчитываться

- Короткий список: что сделал, какие таймкоды поменял, что проверил глазами (и чем), что **не** проверил.
- Если не рендерил или не слушал звук, скажи прямо. «Код компилируется» ≠ «ролик выглядит хорошо».
- Таймкоды давай в секундах и кадрах: «12,4 с (кадр 372)». Пользователь смотрит в плеере секунды, код живёт в кадрах.
- Предлагай 1–2 следующих улучшения, а не десять.

## 2. Пайплайн проекта

```
Исходники → анализ → тайминг-лист → дизайн-система → сцены → звук → QA → рендер → отчёт
```

### 2.1. Анализ исходников (обязательно до кода)

```bash
# параметры видео/аудио
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels -of compact input.mp4

# контактный лист: кадр в секунду, таймкод на каждом
ffmpeg -i input.mp4 -vf "fps=1,scale=384:-1,drawtext=text='%{pts\:hms}':x=6:y=6:fontsize=18:fontcolor=yellow:box=1:boxcolor=black@0.6,tile=6x6" -vsync vfr sheet_%02d.png

# покадровый разбор перехода: 10 кадров/с на 2 секунды начиная с 36,0 с
ffmpeg -ss 36 -t 2 -i input.mp4 -vf "fps=10,scale=384:-1,tile=6x4" -frames:v 1 motion.png

# склейки (scene cut detection)
ffmpeg -i input.mp4 -vf "scale=480:-1,scdet=threshold=8" -an -f null - 2>&1 | grep -oE "lavfi.scd.time: [0-9.]+"

# громкость (интегральная, диапазон, true peak)
ffmpeg -i input.mp4 -af ebur128=peak=true -f null - 2>&1 | tail -12

# паузы в речи
ffmpeg -i voice.wav -af silencedetect=n=-35dB:d=0.25 -f null - 2>&1 | grep silence_

# картинка волны и спектрограмма, чтобы «увидеть» звук
ffmpeg -i input.mp4 -filter_complex "showwavespic=s=2400x300" -frames:v 1 wave.png
ffmpeg -i input.mp4 -lavfi "showspectrumpic=s=2400x500:legend=1:scale=log" spec.png
```

Контактные листы и покадровые тайлы **смотри сам**: это твои глаза. Из них ты узнаёшь стиль, ритм и места, где есть проблемы.

### 2.2. Тайминг-лист (сценарий в секундах)

До кода составь таблицу. Это главный документ проекта, и пользователь легко правит его словами.

| # | Сцена | Начало, с | Длит., с | Голос/текст | Визуал | Звук |
|---|---|---|---|---|---|---|
| 1 | Логотип | 0,0 | 3,5 | — | логотип blur-in, держим, blur-out | мягкий riser → hit на 0,4 с |
| 2 | Итоги года | 3,5 | 10,5 | «Итоги трёх кварталов…» | столбцы растут по очереди, числа считают | тик на каждый столбец |
| … | | | | | | |

Если есть голос, тайминг строится **от голоса** (транскрипция с таймкодами слов, см. раздел 10). Если голоса нет, но есть музыка, тайминг строится **от музыки** (биты, такты, смена частей).

### 2.3. Дизайн-система до сцен

Зафиксируй в одном файле `src/theme.ts`: цвета, шрифты и размеры, отступы, радиусы, стандартные длительности и кривые. Сцены берут значения только оттуда. Так ролик выглядит цельным, а правка «сделай красный потемнее» — это одна строка.

## 4. Архитектура проекта и кода

### 4.1. Структура

```
src/
  index.ts              registerRoot
  Root.tsx              все <Composition>, папки сцен
  theme.ts              цвета, шрифты, размеры, тайминги, кривые
  timeline.ts           таймкоды сцен и событий в секундах (единый источник правды)
  lib/
    anim.ts             хелперы: enter(), exit(), stagger, кривые
    audio.ts            SFX-хелпер, ducking
  components/           переиспользуемые элементы: Title, Bullet, Highlight, Counter, Icon3D, Background
  scenes/
    01-Intro.tsx
    02-Results.tsx
    ...
  Video.tsx             склейка сцен (Series/TransitionSeries) + звуковые дорожки
public/
  fonts/ img/ sfx/ music/ voice/
```

### 4.2. Правила кода

1. **Время в секундах в данных, в кадрах в коде.** Хелпер `const s = (sec: number) => Math.round(sec * fps)`. В `timeline.ts` всё хранится в секундах: так проще сверять с плеером и голосом.
2. **Каждая сцена — свой компонент и свой файл**, своё локальное время (внутри `Sequence` кадр начинается с 0). Существенные сцены регистрируй отдельными `<Composition>` в `<Folder>`, чтобы смотреть их в Studio изолированно.
3. **Длительность композиции вычисляй, не хардкодь.** Сумма сцен минус переходы, или `calculateMetadata` от длительности голоса/музыки.
4. **Детерминизм.** Случайность только через `random('seed-' + i)` из `remotion`. Никаких `useState` для анимации, никаких эффектов, которые зависят от предыдущего кадра.
5. **Асинхронная загрузка данных:** `delayRender()` / `continueRender()`. Шрифты через `loadFont()`: он сам ждёт загрузки.
6. **Медиа:** `<Img>` / `<Video>` / `<Audio>` из Remotion и `@remotion/media`, а не `<img>`/`<video>`. Файлы в `public/`, путь через `staticFile()`.
7. **Анимационные значения пиши прямо в `style`**, используй свойства `scale`, `translate`, `rotate`, а не строку `transform` (Studio умеет их редактировать). Строку `transform` бери, только когда важен порядок трансформаций или нужен `skew`/`perspective`.
8. **Всегда клампуй:** `extrapolateLeft: 'clamp', extrapolateRight: 'clamp'`. Неклампнутый `interpolate` — самая частая причина «элемент улетел» или «прозрачность 1,7».
9. **Премаунт** тяжёлых сцен и видео: `<Sequence premountFor={fps}>`. Иначе первые кадры сцены могут быть пустыми.
10. **Производительность:** большие `filter: blur()` на полноэкранных слоях и десятки `box-shadow` медленно рендерятся. Размывай маленькие элементы, фон заранее рендери в видео/картинку, если он тяжёлый.
11. **Перед сдачей:** `npx tsc --noEmit` и `npx eslint src` без ошибок.

## 5. Анимация: как делать «не топорно»

### 5.1. Базовый механизм

```tsx
const frame = useCurrentFrame();
const {fps} = useVideoConfig();

const p = interpolate(frame, [0.2 * fps, 0.7 * fps], [0, 1], {
  extrapolateLeft: 'clamp',
  extrapolateRight: 'clamp',
  easing: Easing.bezier(0.16, 1, 0.3, 1),
});

// или пружина: physically-based, без жёсткой длительности
const sp = spring({frame: frame - 0.2 * fps, fps, config: {damping: 200}}); // 0→1 без отскока
```

Нормализованный прогресс `p` (0→1) — самый удобный инструмент: одно значение раскладываешь на несколько свойств.

```tsx
style={{
  opacity: p,
  translate: `0px ${(1 - p) * 40}px`,
  filter: `blur(${(1 - p) * 12}px)`,
  scale: 0.96 + 0.04 * p,
}}
```

### 5.2. Кривые: что когда

| Кривая | Где | Ощущение |
|---|---|---|
| `bezier(0.16, 1, 0.3, 1)` (expo-out) | появления, въезды, раскрытия | уверенно, «дорого», без инерции в конце |
| `bezier(0.33, 1, 0.68, 1)` (cubic-out) | спокойные появления, длинные пути | мягче expo |
| `bezier(0.65, 0, 0.35, 1)` (inOut) | перемещение объекта из A в B, камера | плавный разгон и торможение |
| `bezier(0.7, 0, 0.84, 0)` (expo-in) | уходы, «улёт» за кадр | ускоряется и исчезает |
| `spring({damping: 200})` | универсальный вход без отскока | естественно |
| `spring({damping: 12–15, stiffness: 120–180})` | лёгкий перелёт для игривых элементов (иконка, бейдж) | живо; **не для текста и не везде** |
| `linear` | бесконечный дрейф фона, вращение, бегущая строка, счётчик времени | механически |

**Отскок (bounce)** — специя: 1–2 элемента в ролике, не больше. Отскакивающий текст почти всегда выглядит дёшево.

### 5.3. Длительности (30 fps; при 60 fps умножай кадры на 2, секунды те же)

| Действие | Секунды | Кадры @30 |
|---|---|---|
| микро (подсветка, щелчок, смена цвета) | 0,15–0,25 | 5–8 |
| вход элемента | 0,4–0,6 | 12–18 |
| выход элемента | 0,25–0,35 | 8–10 |
| перемещение объекта по кадру | 0,6–0,9 | 18–27 |
| переход между сценами | 0,4–0,8 | 12–24 |
| шаг стаггера | 0,06–0,12 | 2–4 |
| минимальное время чтения | 0,25 с на слово + 1 с | — |

Если не уверен — делай **быстрее**. Медленная анимация — главный признак любительского ролика.

### 5.4. Принципы, которые отличают профи

1. **Стаггер и иерархия.** Сначала главное (заголовок), через 0,15–0,3 с второстепенное (подзаголовок), затем детали (пункты по одному). Внутри группы шаг 2–4 кадра.
2. **Перекрытие (overlap).** Следующее действие начинается, когда предыдущее пройдено на 60–80 %, а не после полной остановки. Никаких «мёртвых» кадров между фазами.
3. **Асимметрия входа и выхода.** Вход 0,5 с с ease-out, выход 0,3 с с ease-in, часто все элементы выходят разом.
4. **Малые амплитуды.** Сдвиг 20–60 px, масштаб 0,9→1 или 1,05→1, поворот ≤ 5°. Большие пролёты оставь для осознанных акцентов.
5. **Blur как motion blur.** Размытие 8–16 px на входе/выходе имитирует движение камеры и сглаживает появление. Это главный приём в эталоне (раздел 12).
6. **Маски вместо fade.** Текст выезжает из-под невидимой границы (`overflow: hidden` + translateY 100 % → 0). Плашка «растёт» слева направо (`clipPath: inset(0 X% 0 0)` или `scaleX` с `transformOrigin: left`).
7. **Вторичное движение.** Пока главный объект стоит, что-то живёт: медленный наезд (scale 1→1,04 за 5 с), дрейф фона, «дыхание» иконки (±1,5 % масштаба, синус с периодом 3–4 с), лёгкий параллакс слоёв.
8. **Фокус-менеджмент.** Когда появляется новый пункт, предыдущий приглушается (opacity 0,45 или серый цвет). Взгляд всегда знает, куда смотреть.
9. **Связь между сценами (continuity).** Элемент из сцены A становится элементом сцены B: иконка из сетки улетает и становится героем следующей сцены, заголовок уменьшается и становится шапкой. Это убирает ощущение слайдов.
10. **Числа считают.** Проценты и суммы набираются от 0 (или от прошлого значения) с ease-out за 0,8–1,5 с, в табличных цифрах, без дёрганья ширины.
11. **Один акцент на экран в момент времени.** Если в кадре одновременно двигаются три независимых вещи, зритель не понимает, куда смотреть.

### 5.5. Анти-паттерны («топорно»)

- Всё появляется в один кадр и одним fade.
- `interpolate` без easing и без clamp.
- Одинаковая анимация на всём (каждый элемент «выпрыгивает» с отскоком).
- Элементы въезжают с края экрана через весь кадр.
- Вращения на 360°, «вертолёты» текста, тряска без смысла.
- Долгие холды без движения, затем резкая смена.
- Текст появляется раньше, чем его можно прочитать, или исчезает до конца фразы.
- Переход «звёздочкой»/«шторкой» между каждыми сценами.
- Тени `0 0 20px black` вокруг всего, обводки текста, градиент «радуга».
- Разные шрифты в каждой сцене, пять цветов акцента.
- Анимация «ради анимации», не связанная с голосом и смыслом.

## 6. Типографика и текст

### 6.1. Шрифты

- **Максимум два семейства:** акцидентный (заголовки) + текстовый, либо одно семейство с разными весами. Чаще всего хватает одного гротеска в весах 500/700/900.
- **Кириллица обязательна.** Всегда передавай `subsets: ['cyrillic', 'latin']`. Проверяй, что у шрифта есть кириллица: у части популярных латинских дисплейных шрифтов (например, Bebas Neue в Google Fonts) её нет, браузер подставит системный фолбэк, и ролик развалится.
- Хорошие кириллические гротески в Google Fonts: Inter, Manrope, Onest, Golos Text, Montserrat, Unbounded (широкий, для заголовков), Rubik, Raleway, Exo 2, Russo One, Oswald (узкий). Антиквы: PT Serif, Playfair Display, Lora.
- Широкие жирные капсом заголовки (как в эталоне) — сильный приём для корпоративных итогов и промо.

```ts
import {loadFont} from '@remotion/google-fonts/Inter';
const {fontFamily} = loadFont('normal', {weights: ['600', '800', '900'], subsets: ['cyrillic', 'latin']});
```

### 6.2. Размеры для 1920×1080

| Роль | Кегль, px | Начертание | Межстрочный | Трекинг |
|---|---|---|---|---|
| Hero-цифра («+2,9 %») | 160–260 | 900 | 0,9–1,0 | −0,02 em |
| Заголовок сцены | 64–110 | 800–900 | 1,0–1,1 | −0,01 em, капс +0,02 em |
| Подзаголовок / пункт | 32–48 | 600–800 | 1,15–1,25 | 0 |
| Подпись, мелкий текст | 22–28 | 600 | 1,3 | +0,02 em |

Для вертикали 1080×1920 основной текст крупнее (44–64 px), а строки короче. Мельче 22 px на 1080p не ставь: после сжатия соцсетей это каша.

### 6.3. Правила набора

- Строка ≤ 30–40 знаков, заголовок ≤ 2–3 строк. Переносы ставь вручную, по смыслу; `textWrap: 'balance'` выравнивает строки.
- **Русская типографика:** «ёлочки», тире «—» (не дефис), неразрывный пробел (` `) после коротких предлогов и союзов (в, на, с, и, к, по, за, от) и между числом и единицей (`2,9 %`, `5 пилотов`). Буква «ё» там, где она есть.
- Десятичная запятая в русском тексте: `40,0 %`. Для счётчиков используй `Intl.NumberFormat('ru-RU')`.
- Для меняющихся чисел: `fontVariantNumeric: 'tabular-nums'`. Иначе ширина прыгает и текст рядом дёргается.
- Контраст: белый по тёмному, акцентная плашка с белым текстом. Текст поверх видео — на подложке или с мягкой тенью `0 2px 12px rgba(0,0,0,.5)`.
- **Выделение ключевых слов:** плашка акцентного цвета под словом (как «малоэффективные», «новые» в эталоне), а не другой шрифт и не подчёркивание.
- Если текст может не влезть (динамические данные), меряй его: `measureText` / `fitText` из `@remotion/layout-utils`.

### 6.4. Кинетическая типографика: приёмы

| Приём | Как сделать | Когда |
|---|---|---|
| Blur-in | opacity 0→1, blur 12→0, translateY 20→0 | универсальный, «дорогой» |
| Mask reveal | строка в `overflow:hidden`, текст translateY 100 %→0 | заголовки, строгий стиль |
| По словам | стаггер 2–3 кадра на слово | фразы под голос |
| По буквам | стаггер 1 кадр, только короткие слова | логотипы, акценты; не для абзацев |
| Плашка-маркер | фон растёт слева направо (clipPath/scaleX), затем текст белеет | ключевые слова |
| Счётчик | число от A до B, ease-out | проценты, деньги, метрики |
| Печатная машинка | `text.slice(0, n)` + курсор | интерфейсы, код, «документ» |
| Масштабный перелёт | заголовок на весь экран → уменьшается в шапку | вход в раздел (эталон, «Мероприятия SAVE 2026») |

## 7. Цвет, фон, глубина, композиция кадра

### 7.1. Палитра

- Фон + основной цвет текста + **один** акцент + приглушённый вариант текста. Всё остальное — производные (прозрачности).
- Чистый `#000` и чистый `#fff` на больших площадях выглядят плоско. Фон — `#0a0a0c`…`#121216`, либо градиент с виньеткой.
- Акцент несёт смысл (рост, внимание, «главное»). Не крась им декоративные мелочи.
- Бренд-цвета бери из логотипа/гайда пользователя (пипеткой со скриншота), а не «примерно красный».

### 7.2. Фон — живой, но тихий

- Анимированные абстракции: диагональные световые полосы, волны линий, мягкие пятна-градиенты, шум. Медленный (цикл 6–20 с), низкий контраст, не спорит с текстом.
- **Два-три типа фона на ролик с разной ролью.** В эталоне: яркие диагональные полосы для «разделов-событий» (интро, итоги, обзор, финал) и тёмные волны линий для «подробностей» (сцены с пунктами). Смена фона сама сообщает зрителю, на каком уровне он находится.
- Градиенты на 8-битном видео дают бандинг (ступеньки). Лечится лёгким зерном/шумом поверх (opacity 0,03–0,06).
- Виньетка (радиальный градиент к краям 30–50 % черноты) собирает взгляд в центр.
- Размытый кадр исходника как фон для врезок (blur 30–60 px, затемнение 40–60 %) — дешёвый и стильный способ сохранить связь с видео.

### 7.3. Глубина

- Слои: фон (медленно) → средний план (объекты) → передний план (текст, частицы). Параллакс: чем ближе слой, тем больше смещение при движении камеры.
- Тени мягкие и многослойные: `0 20px 60px rgba(0,0,0,.45), 0 4px 12px rgba(0,0,0,.3)`. Для свечения акцентных элементов: `0 0 40px rgba(акцент, .5)`.
- 3D-иконки (как в эталоне) должны быть **одного стиля**: один свет, один материал, одна цветовая гамма (белый пластик + красный акцент + хром). Набор из разных стоков сразу выдаёт любительщину.

### 7.4. Композиция кадра

- Поля: ≥ 80–120 px от краёв на 1080p (title safe ~5 %). Для вертикальных соцсетей верх ~220 px и низ ~380 px закрыты интерфейсом, справа ~120 px — кнопками.
- Сетка: одна для всего ролика (например, 12 колонок, левый край текста всегда на одной линии). В эталоне все сцены-подробности собраны одинаково: заголовок слева сверху, объект слева, пункты справа от объекта. Зритель не ищет информацию, он знает, где она.
- Один фокус на кадр. Пустое место — не проблема, а воздух.
- Выравнивай по оптическому, а не только по математическому центру (крупные цифры, знаки «+», «%», кавычки свисают).

## 8. Монтаж: ритм, склейки, переходы

### 8.1. Ритм

- Хук в первые 1–2 с (для соцсетей — в первую секунду). Логотип в начале — максимум 1,5–3 с.
- Новая визуальная информация каждые 1,5–4 с. Если по голосу сцена длинная, добавляй внутри неё события: новый пункт, наезд, подсветку.
- Чередуй плотность: насыщенный экран → «воздух» (одна крупная фраза) → снова плотный. В эталоне так работают «+2,9 %» и «Выглядит впечатляюще?» между графиками и сетками.
- Финал: подвести итог, дать 1–2 с на последний кадр, затем логотип/CTA и затухание звука.

### 8.2. Склейки

- **Жёсткая склейка — по умолчанию.** Хорошо, когда она стоит на долю/бит музыки или на начале фразы.
- Монтаж «по действию»: склейка в середине движения (элемент начал улетать в A и долетел в B) маскирует стык.
- **J/L-склейки** в видео с речью: звук следующей сцены начинается на 3–10 кадров раньше картинки (J) или звук предыдущей тянется под новую картинку (L). Убирает «рваность».
- Каждую склейку проверяй на кадрах `cut−1`, `cut`, `cut+1`: нет ли чёрного кадра, вспышки, повтора кадра.

### 8.3. Переходы

- Набор на ролик: **1–2 типа**, применяемые последовательно. Например, «blur-dissolve 0,4 с» для всех смен внутри раздела и «пролёт через линию» для смены разделов.
- `TransitionSeries` укорачивает таймлайн на длину перехода (сцены перекрываются). Учитывай это в общей длительности. `TransitionSeries.Overlay` (например, засветка) таймлайн не укорачивает.
- Свои переходы проще всего делать без библиотеки: сцена A на последних N кадрах делает exit, сцена B на первых N кадрах — enter, `Sequence`'ы перекрываются на N кадров.
- **Shared element** (магический переход) — объект из сцены A и тот же объект в B. Рендери его на уровне выше сцен и интерполируй позицию/масштаб между двумя раскладками (паттерн в разделе 11.6).
- Каждый заметный переход озвучивается (whoosh, swoosh, мягкий удар), иначе он кажется «немым».

### 8.4. Работа с исходным видео

```tsx
import {Video} from '@remotion/media';

<Sequence from={s(12)} durationInFrames={s(4)}>
  <Video src={staticFile('source.mp4')} trimBefore={s(30)} playbackRate={1} volume={0.8} />
</Sequence>
```

- `trimBefore`/`trimAfter` — в кадрах исходника. При `playbackRate ≠ 1` длительность куска в таймлайне = длина исходного куска / rate.
- Стоп-кадр: `<Freeze frame={0}><Video … /></Freeze>`.
- Перекрывающие врезки поверх исходника: отдельный `<Sequence>` выше в JSX (позже в разметке = выше по слоям). Звук исходника продолжает идти.
- Тишину и паузы в речи для «джамп-катов» находи через `silencedetect`, вырезай кусками `Sequence` + `trimBefore`.

## 9. Звук: голос, музыка, SFX

### 9.1. Слои и уровни

| Слой | Роль | Ориентир громкости |
|---|---|---|
| Голос | главный | пики −6…−3 dBFS, интеграл итогового микса −14…−16 LUFS |
| Музыка под голосом | подложка | на 15–25 dB тише голоса; в Remotion обычно `volume` 0,08–0,2 (зависит от мастеринга трека: меряй, не угадывай) |
| Музыка без голоса | ведущая | `volume` 0,5–1 |
| SFX-акценты | пунктуация | чуть тише голоса; удары/вжухи `volume` 0,3–0,6, UI-щелчки 0,15–0,35 |
| Эмбиент / рум-тон | склейка пространства | едва слышно, 0,03–0,1 |

Итоговый файл: **−14 LUFS** для YouTube и соцсетей (−16 для спокойных корпоративных роликов тоже нормально), true peak ≤ −1 dBTP, без клиппинга. `volume` в Remotion — линейный множитель: −6 dB ≈ 0,5, −12 dB ≈ 0,25, −20 dB = 0,1.

Мерить после рендера:

```bash
ffmpeg -i out/video.mp4 -af ebur128=peak=true -f null - 2>&1 | tail -12
```

Если громкость не та, правь `volume` в коде, а не нормализуй готовый файл. Пользователь потом будет менять код, и нормализация потеряется.

### 9.2. Музыка: как выбирать

1. **Настроение и жанр — из брифа.** Корпоративные итоги: современный электронный/кинематографичный пульс, уверенно, без вокала. Промо продукта: энергичный поп/электро. Объяснялка: лёгкий lo-fi/акустика. Мемное: тренд-звук по запросу пользователя.
2. **Темп = темп монтажа.** 80–100 BPM — спокойно; 110–128 — уверенно, деловито; 130–150 — хайп, быстрые склейки.
3. **Без вокала под голосом.** Вокал в музыке спорит с диктором за внимание.
4. **Структура трека повторяет структуру ролика:** интро трека под интро, рост (build) под нарастание, «дроп» под главный момент, аутро под финал. Если трек длиннее ролика, не обрезай его на середине такта.
   - Подгоняй **конец** трека под конец ролика: `from = totalFrames − musicFrames`, начало при этом обрезается или уходит в fade-in. Финальный аккорд, который совпадает с логотипом, — признак профессионального монтажа.
   - Или режь трек по тактам (`aubio beat` → такты по 4 доли) и склеивай части с кроссфейдом 0,1–0,3 с на сильной доле.
5. Fade-in 0,3–1 с в начале, fade-out 1–3 с в конце. Никогда не обрывай музыку на полуслове.

### 9.3. Даккинг (музыка уходит под голос)

```tsx
// voiceSegments: [[startSec, endSec], ...] из транскрипции или silencedetect
const duck = (f: number) => {
  const t = f / fps;
  const DUCKED = 0.12, FULL = 0.35, RAMP = 0.25; // секунды на наклон
  let k = 0;
  for (const [a, b] of voiceSegments) {
    const up = interpolate(t, [a - RAMP, a], [0, 1], {extrapolateLeft: 'clamp', extrapolateRight: 'clamp'});
    const down = interpolate(t, [b, b + RAMP * 2], [1, 0], {extrapolateLeft: 'clamp', extrapolateRight: 'clamp'});
    k = Math.max(k, Math.min(up, down));
  }
  return FULL + (DUCKED - FULL) * k;
};

<Audio src={staticFile('music/track.mp3')} volume={(f) => duck(f)} />
```

Если голос идёт почти без пауз (как в эталоне), даккинг не нужен: ставь музыку ровно тихо (0,08–0,15) и дай ей «подняться» только в паузах-акцентах и в финале.

### 9.4. SFX: как подставлять грамотно

**Что озвучивать.** Только события, которые зритель должен «почувствовать»:
- смена раздела/сцены (whoosh, swoosh, мягкий удар);
- появление главного объекта или цифры (hit, «бум», тихий сабовый удар);
- UI-события (щелчок, тик, pop, переключатель) — если стиль интерфейсный;
- рост числа (короткие тики или нарастающий тон), печать текста (клавиши);
- финальный логотип (riser → hit или «шиммер»).

**Чего не делать:**
- не озвучивать каждый пункт и каждое слово (максимум один SFX на 1–2 с, если это не намеренный «тиканье»-стиль);
- не повторять один и тот же файл 20 раз подряд: чередуй 2–3 варианта или меняй громкость ±20 %;
- не ставить мемные звуки в корпоративный ролик без явной просьбы.

**Тайминг — самое важное:**
- **Удар (transient) звука — ровно на кадре визуального события** или на 1 кадр позже. Звук, опережающий картинку больше чем на ~40 мс, мозг замечает как рассинхрон. Отставание до ~100 мс воспринимается как естественное.
- **Whoosh:** пик громкости вжуха — на моменте максимальной скорости движения (середина пролёта). Значит, файл стартует раньше движения на «длину нарастания» вжуха.
- **Riser:** заканчивается ровно на кадре раскрытия (hit).
- **У файлов почти всегда есть тишина в начале.** Меряй её и компенсируй:

```bash
# сколько тишины до атаки (silence_end первой строки)
ffmpeg -i public/sfx/whoosh.wav -af silencedetect=n=-40dB:d=0.005 -f null - 2>&1 | grep -m1 silence_end
# пик громкости (для вжуха): позиция максимума
ffmpeg -i public/sfx/whoosh.wav -af "astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.Peak_level" -f null - 2>&1 | head
```

Храни это в данных: `{src, attack: 0.012, peak: 0.21}` и ставь звук с поправкой.

```tsx
// lib/audio.ts
import {Audio} from '@remotion/media';
import {Sequence, staticFile, useVideoConfig} from 'remotion';

type Sfx = {src: string; attack?: number; peak?: number}; // секунды от начала файла
export const SFX = {
  whoosh: {src: 'sfx/whoosh.wav', peak: 0.18},
  hit: {src: 'sfx/hit.wav', attack: 0.01},
  click: {src: 'sfx/click.wav', attack: 0.004},
} satisfies Record<string, Sfx>;

// at — секунда визуального события; align — чем совпасть с событием
export const SfxAt: React.FC<{sfx: Sfx; at: number; volume?: number; align?: 'attack' | 'peak'}> = ({
  sfx, at, volume = 0.5, align = 'attack',
}) => {
  const {fps} = useVideoConfig();
  const offset = (align === 'peak' ? sfx.peak : sfx.attack) ?? 0;
  const from = Math.round((at - offset) * fps);
  return (
    <Sequence from={from} layout="none" name={`sfx ${sfx.src} @${at}s`}>
      <Audio src={staticFile(sfx.src)} volume={volume} />
    </Sequence>
  );
};
```

Если `from` получается отрицательным (событие в самом начале), отрежь начало файла через `trimBefore`, а не сдвигай событие.

**Слоение для крупных акцентов:** whoosh (высокие) + низкий удар/саб (вес) + короткий «шиммер» (воздух). Каждый слой тихий, вместе они звучат «дорого».

**Синхронизация с музыкой:** если есть биты (`aubio beat track.wav > beats.txt`), снапь ключевые события (склейки, появления hero-элементов) к ближайшей доле в пределах ±3 кадров. Не нужно ставить на бит всё: достаточно смен разделов и главных акцентов.

### 10.1. Голос → таймкоды

### 11.1. Хелперы времени и прогресса

```ts
// lib/anim.ts
import {Easing, interpolate, spring} from 'remotion';

export const EASE_OUT = Easing.bezier(0.16, 1, 0.3, 1);
export const EASE_IN = Easing.bezier(0.7, 0, 0.84, 0);
export const EASE_IN_OUT = Easing.bezier(0.65, 0, 0.35, 1);

const clamp = {extrapolateLeft: 'clamp', extrapolateRight: 'clamp'} as const;

/** 0→1 начиная с startF за durF кадров */
export const prog = (frame: number, startF: number, durF: number, easing = EASE_OUT) =>
  interpolate(frame, [startF, startF + durF], [0, 1], {...clamp, easing});

/** вход и выход в одном значении: 0→1 … 1→0 */
export const inOut = (frame: number, inF: number, inDur: number, outF: number, outDur: number) =>
  Math.min(prog(frame, inF, inDur, EASE_OUT), 1 - prog(frame, outF, outDur, EASE_IN));

export const springIn = (frame: number, fps: number, delayF = 0, damping = 200) =>
  spring({frame: frame - delayF, fps, config: {damping}});
```

### 11.6. Shared element: объект перелетает из сетки в героя сцены

```tsx
type Box = {x: number; y: number; size: number};

export const FlyIcon: React.FC<{src: string; from: Box; to: Box; at: number; dur?: number}> = ({src, from, to, at, dur = 0.7}) => {
  const frame = useCurrentFrame();
  const {fps} = useVideoConfig();
  const p = prog(frame, Math.round(at * fps), Math.round(dur * fps), EASE_IN_OUT);
  const x = from.x + (to.x - from.x) * p;
  const y = from.y + (to.y - from.y) * p;
  const size = from.size + (to.size - from.size) * p;
  return (
    <Img src={staticFile(src)} style={{
      position: 'absolute', left: x - size / 2, top: y - size / 2, width: size, height: size,
      filter: `drop-shadow(0 ${size * 0.06}px ${size * 0.12}px rgba(0,0,0,.5))`,
    }} />
  );
};
```

Сетка в это время уходит: остальные иконки blur + opacity → 0, фон меняется кроссфейдом. Объект рендерится **поверх** обеих сцен, на уровне `Video.tsx`, чтобы не обрезаться границами `Sequence`.

### 11.10. Склейка сцен со своими переходами (перекрытие)

```tsx
// Video.tsx
const OVERLAP = 0.4; // с: выход A и вход B идут одновременно
const scenes = [
  {Scene: Intro, dur: 3.5},
  {Scene: Results, dur: 10.5},
  {Scene: Overview, dur: 9},
];

export const Main: React.FC = () => {
  const {fps} = useVideoConfig();
  let cursor = 0;
  return (
    <AbsoluteFill style={{background: C.bg}}>
      {scenes.map(({Scene, dur}, i) => {
        const from = Math.round(cursor * fps);
        cursor += dur - OVERLAP;
        return (
          <Sequence key={i} from={from} durationInFrames={Math.round(dur * fps)} premountFor={fps}>
            <Scene />
          </Sequence>
        );
      })}
      <Audio src={staticFile('voice.wav')} />
      <Audio src={staticFile('music/track.mp3')} volume={0.12} />
    </AbsoluteFill>
  );
};
// длительность композиции: сумма dur − OVERLAP × (n − 1)
```

Каждая сцена сама анимирует свой вход (первые 0,4 с) и выход (последние 0,4 с), используя `durationInFrames` из `useVideoConfig()`.

## 12. Разбор эталона: «ГЗК — Мероприятия SAVE 2026»

Файл: `ГЗК_Мероприятия_Save_2026_v2_сжатый.mp4` — 1920×1080, **60 fps**, 3:25, H.264 ~4,6 Мбит/с, AAC 48 кГц стерео. Корпоративный ролик-отчёт: итоги трёх кварталов и 11 мероприятий, за счёт которых вырос показатель. Разобран по контактным листам (1 кадр/с) и покадровым тайлам переходов (10 кадров/с). Ниже — что именно делает его качественным, в виде правил, которые можно повторить.

### 12.1. Драматургия и структура

| Время | Блок | Приём |
|---|---|---|
| 0:00–0:04 | Логотип | логотип на ярком фоне, уход в размытие |
| 0:04–0:14 | «Итоги трёх кварталов 2026» | столбчатая диаграмма: столбцы растут по очереди, проценты считают от нуля, последний столбец — акцентный красный |
| 0:14–0:18 | «+2,9 %» | диаграмма уходит в размытие, на её месте огромная hero-цифра считает от +0,0 % до +2,9 %, под ней плашка «Конверсия сохранения» и подпись «с начала года: 37,1 % → 40,0 %» |
| 0:18–0:22 | «За счёт чего» | hero-цифра уменьшается и уезжает влево, справа появляется таблица вкладов по строкам |

| 0:24–0:36 | «Мероприятия SAVE 2026» | заголовок на весь экран → уменьшается в шапку; под ним сетка из 11 3D-иконок появляется волной слева направо; внизу подпись-плашка |

| 2:55–2:58 | «Но на этом наша работа не заканчивается» | пауза-поворот, ключевое слово «не» на плашке |
| 2:58–3:19 | «Новые вызовы» | 4 вызова появляются по одному в сетке 2×2 |
| 3:20–3:25 | Логотип | тот же логотип и фон, что в начале: рамка ролика замкнута |

**Вывод для агента.** Ролик построен как *хаб и спицы*: обзорный экран-оглавление, из него вход в каждый пункт и возврат обратно. Зритель всегда понимает, где он и сколько осталось. Для любого ролика-перечня (функции продукта, итоги, этапы) это лучшая структура.

### 12.2. Визуальная система

- **Палитра:** чёрный + белый + один красный. Красный только на смысловых местах: последний (лучший) столбец, плашки ключевых слов, акценты 3D-иконок.
- **Два фона с разной ролью.** Яркие диагональные красные световые полосы — для «верхнего уровня» (логотип, итоги, оглавление, финал). Тёмные, почти чёрные волны тонких красных линий — для подробностей. Смена фона — навигационный сигнал.
- **Шрифт:** один широкий жирный гротеск, капс, для заголовков и пунктов. Иерархия только размером и цветом.
- **Плашки ключевых слов:** красный прямоугольник под 1–2 словами в каждом пункте («малоэффективные», «новые инструменты», «глубокая аналитика», «не было улучшений»). Читатель схватывает смысл, не читая всё.
- **3D-иконки единого стиля:** белый глянцевый пластик, хром, красные детали, одинаковый свет. Шапочка, график, рубин, апельсин, скрещённые руки, бабл чата, ракета, блокнот, перечёркнутая стрелка, вопросительный знак, робот. Набор выглядит как сделанный одним художником.
- **Сетка раздела неизменна:** заголовок в 2–3 строки слева сверху, большая 3D-иконка слева, пункты справа от иконки. Меняется только содержание.

### 12.3. Цикл раздела (повторён 11 раз — повторяемость и есть стиль)

Покадрово, на примере 0:51–0:53 и 2:34–2:36:

1. **Уход раздела (~0,3 с).** Весь раздел (заголовок, иконка, пункты) одновременно размывается и гаснет. Отдельные элементы не уезжают: синхронный blur-out читается как «закрыли страницу».
2. **Возврат в оглавление (~0,2 с).** Сетка иконок проявляется из размытия. Уже пройденные пункты приглушены и обесцвечены, следующий — яркий: прогресс виден без слов.
3. **Сканирующая линия.** Тонкая горизонтальная красная линия проходит через кадр. Это фирменная «склейка» ролика, она же стоит между интро и итогами (0:03–0:04) и перед «Выглядит впечатляюще?».
4. **Фокус (~0,5 с).** Выбранная иконка подсвечена, остальные гаснут ещё сильнее.
5. **Перелёт (~0,4–0,6 с).** Выбранная иконка растёт и летит из своей ячейки в позицию героя слева. Остальная сетка и шапка уходят в размытие, фон перетекает в «волны». Это shared element: объект не исчезает и не появляется заново, а *переходит* между сценами.
6. **Заголовок раздела (~0,3 с).** Проявляется из размытия поверх уходящей шапки оглавления.
7. **Пункты по голосу.** Через 1–5 с первый пункт: строки проявляются из размытия со сдвигом слева, плашка ключевого слова растёт слева направо. Второй пункт приходит через 2–4 с. **Предыдущий пункт в этот момент становится серым** (фокус-менеджмент).
8. **Холд** до конца фразы диктора, затем снова шаг 1.

Весь переход «раздел → сетка → новый раздел» укладывается примерно в 2 с: быстро, но читаемо.

### 12.4. Работа с данными

- Столбцы растут снизу по очереди с шагом ~0,5 с. Число над столбцом считает синхронно с ростом высоты.
- Hero-цифра считает от «+0,0 %» до «+2,9 %» примерно за 1,2 с с замедлением в конце. Подпись и плашка приходят, когда число почти досчитало: не раньше.
- Таблица вкладов: строки появляются сверху вниз, значения справа набираются.

### 12.5. Звук

- Голос диктора почти без пауз на всём ролике + ровная музыкальная подложка. Сигнал собран к центру (энергия боковой составляющей ниже средней примерно на 19 dB), что типично для доминирующего голоса.
- Громкость: −16,8 LUFS интегрально, true peak −2,8 dBFS, LRA 4,1 LU — плотный ровный микс, комфортный для корпоративного показа. Для соцсетей можно поднять до −14 LUFS.
- Самые заметные широкополосные акценты на спектрограмме — около 0:14 (старт hero-цифры) и около 3:20 (финальный логотип). **Акцентные SFX экономно, только на главных событиях**, остальное держит голос.

### 12.6. Что можно сделать лучше (зоны роста)

- Около 1:01 и 1:46 есть почти пустые кадры (~0,1–0,2 с) между уходом раздела и проявлением сетки. Перекрытие 2–4 кадра между выходом и входом уберёт «провал».
- Длинные холды внутри разделов (до 4–5 с без нового события, пока говорит диктор). Здесь помог бы медленный наезд камеры или «дыхание» 3D-иконки: кадр останется спокойным, но живым.
- Пункты мелкие для экрана ноутбука (на 1080p примерно 22–28 px по высоте строки). Для показа в зале нормально, для просмотра в мессенджере стоит поднять до 32+ px.

### 12.7. Как воспроизвести такой ролик в Remotion (план)

1. `theme.ts`: чёрный/белый/красный, один широкий гротеск (например, Unbounded 800/900 или Montserrat 900, капс), кривые и длительности из раздела 4.3.
2. Компоненты: `Streaks` (11.7), `Waves` (тонкие синусоидальные линии, медленный дрейф), `BlurIn` (11.2), `Mark` (11.4), `Counter` (11.5), `Bullets` с приглушением (11.8), `FlyIcon` (11.6), `ScanLine` (горизонтальная линия 2 px, `left` −10 % → 110 % за 0,4 с с expo-out).
3. Данные разделов в массиве: `{title, icon, bullets: [{text, mark, at}]}`. Сцена раздела — один компонент, 11 экземпляров. Тайминги `at` берутся из транскрипции голоса.
4. `Overview` (сетка) получает индекс текущего раздела: пройденные — серые, текущий — яркий, остальные — приглушённые.
5. Склейка: `[Overview(i) → FlyIcon → Section(i)] × 11`, переход-перекрытие ~0,3 с, `FlyIcon` на верхнем уровне.
6. Звук: голос + музыка 0,1–0,15 + SFX только на hero-моментах (логотип, «+2,9 %», вход в «Новые вызовы», финал) и, по желанию, тихий swoosh на каждом перелёте иконки.

## 13. Проверка качества (QA) и рендер

### 13.1. Смотри, а не надейся

```bash
# стоп-кадры в ключевые моменты (кадры склеек, пики анимаций, середины холдов)
npx remotion still Main out/f0372.png --frame=372

# быстрый черновой рендер для просмотра
npx remotion render Main out/draft.mp4 --scale=0.5 --crf=28

# контактный лист готового рендера (каждые 0,5 с)
ffmpeg -i out/draft.mp4 -vf "fps=2,scale=320:-1,drawtext=text='%{pts\:hms}':x=4:y=4:fontsize=14:fontcolor=yellow:box=1:boxcolor=black@0.6,tile=8x6" -vsync vfr out/sheet_%02d.png

# покадровый тайл вокруг склейки на кадре 372 (±5 кадров @30fps)
ffmpeg -ss $(echo "367/30" | bc -l) -t 0.4 -i out/draft.mp4 -vf "scale=384:-1,tile=6x2" -frames:v 1 out/cut372.png
```

Что проверять на листах:
- нет пустых/чёрных кадров и вспышек на склейках;
- текст не вылезает за поля, не наезжает на объекты, читается;
- кириллица отрисована нужным шрифтом (а не фолбэком);
- ничего не «замирает» дольше 1,5–2 с без причины;
- элементы появляются под голос (сверяй с таймкодами транскрипции).

Звук: `ebur128` (громкость и пики), `silencedetect` на мастере (нет внезапных дыр), волна `showwavespic` (нет клиппинга — плоских срезанных пиков).

### 13.2. Рендер

```bash
# мастер H.264 для соцсетей/мессенджеров
npx remotion render Main out/master.mp4 --codec=h264 --crf=18 --pixel-format=yuv420p --audio-bitrate=320k

# с прозрачностью (для монтажа в другом редакторе)
npx remotion render Overlay out/overlay.mov --codec=prores --prores-profile=4444 --pixel-format=yuva444p10le

# лёгкая версия для пересылки
ffmpeg -i out/master.mp4 -c:v libx264 -crf 26 -preset slow -c:a aac -b:a 160k out/light.mp4
```

- 30 fps — стандарт; 60 fps — для плавной графики (как в эталоне), но рендер вдвое дольше и файл больше.
- `yuv420p` обязателен для совместимости с плеерами, Telegram, iOS.
- Если не скачивается Chrome Headless Shell — `--browser-executable=/путь/к/chrome`.
